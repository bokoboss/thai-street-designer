# Diamond v2 — Slice 1: terminal stations on curved crossroads

Parent tracking: [Issue #83](https://github.com/bokoboss/thai-street-designer/issues/83). Baseline: `main` at `7a89e318` after PR D #82.

## Problem verified by source inspection

`diamondPlan()` in `core/road-first/diamond.ts` samples a ramp terminal position from the crossroad using `pointAt(cross.points, station, cross.alignment)`. This position is on the resolved circular-arc alignment when `alignment = 'arc'`.

Before this slice, terminal elevation `zCross(p)` was computed from the dot product of the displacement from the crossing and the **single tangent at the crossing**, and then adding that approximate offset to the crossing station. On a curved crossroad the tangent projection is not the true alignment station. The ramp and its receiving road can therefore meet at different elevations even though the horizontal terminal point is attached to the road.

## Correction

Resolve the crossroad with `resolveAlignment(cross.points, cross.alignment ?? 'chord')` and query its existing `project(terminal).station`. Pass that station to `levelAt()` against the crossroad's profile after the grade-separation proposal. Both operations now use the same canonical resolved horizontal alignment. Do **not** change ramp XY positions, template defaults, provenance, version 1 metadata, the project schema or the ordinary road/ramp command layer.

## Regression and scope

`scripts/verify-diamond.cjs` adds a non-collinear curved crossroad (`alignment='arc'`) with a non-flat profile generated by the cross-over proposal. Each of four ramp endpoints must match the crossroad elevation at its resolved arc-length station (within the existing 0.01 m two-decimal output rounding), and the fixture asserts that the prior tangent estimate materially differs. All v1 template geometry, footprint/refusal and single-undo tests remain in place.

This change does **not** solve the separate geometry question of where a terminal should be placed on a strongly curved/skew crossroad for a requested perpendicular offset. In this slice, the terminal XY station selection remains the existing approximation, so its plan-distance accuracy and acute/skew geometries stay **TO_VERIFY**. Future v2 work must independently survey and test this geometry before changing it.

The five licensed real-site examples in the roadmap are the v2 closure gate, not a prerequisite to this correctness fix. Do not silently regenerate an existing v1 template group.
